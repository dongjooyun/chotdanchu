# 에이전트 구현 방식

## 화면

챗봇 + 카드 위젯 하이브리드. 모바일 반응형 웹 한 화면.

- 에이전트 응답 안에 위젯(후보 칩, 지표 카드, 맞대결 카드, 리포트)이 렌더링된다.
- 첫 메시지에 빠른 응답 버튼을 두어 시연 중 엉뚱한 입력을 줄인다.
- 옆(모바일에선 접힘)에 "에이전트 판단 로그" 패널: 어떤 도구를 왜 불렀는지 보여준다.

참고 데모: `docs/prototype/chat-tutorial.html`

## 에이전트 루프

1. 시스템 프롬프트 + 세션 상태(구조화된 값) + 최근 대화 몇 턴을 모델에 보낸다.
2. 모델이 다음 도구와 인자를 정한다.
3. 서버가 도구를 실행하고 결과를 돌려준다.
4. 모델이 다음 도구를 부르거나 사용자에게 응답(또는 위젯 표시)한다.
5. 한 요청당 도구 호출 상한 8회. 넘으면 지금까지 결과로 정리해 응답한다.

### 구현 (CDC-14, 11/20)

| 파일 | 하는 일 |
|---|---|
| `lib/agent/loop.ts` | 루프. 도구 호출 상한, 끝나는 도구 처리, 폴백 |
| `lib/agent/tools.ts` | 도구 정의(`search_company`, `show_choices`, `get_company_profile`, `compute_indicators`)와 실행부 |
| `lib/agent/prompt.ts` | 시스템 프롬프트. 날짜 같은 변하는 값을 넣지 않는다 |
| `lib/agent/llm.ts` | LLM 호출 인터페이스. 테스트에서는 가짜를 넣는다 |
| `lib/agent/responses.ts` | 화면 응답 만들기와 정해진 규칙 경로(폴백) |

- `USE_AGENT=true`일 때만 LLM을 부른다. 기본값, 단위 테스트, E2E는 정해진 규칙 경로라 크레딧을 쓰지 않는다
- 모델은 `config.models.small`(`claude-haiku-5-5`), effort `low`. 도구를 고르는 일이라 가벼운 모델로 충분하다
- 도구마다 `reason`(왜 부르는지)을 필수로 받아 판단 로그의 근거로 그대로 보여 준다
- `show_choices`, `compute_indicators`를 부르면 그 자리에서 끝난다. 답 문장과 숫자는 코드가 만들고, LLM 문장은 도구 없이 답할 때만 쓴다
- LLM 호출이 실패하거나 거절하면 정해진 규칙으로 대신 답하고 `fallback` 로그를 남긴다. 상한에 닿으면 `limit` 로그
- LLM에 보내는 도구 결과에는 대표자 이름을 넣지 않는다
- 후보 칩을 고른 요청(`pickCompanyId`)은 사용자가 이미 정한 것이라 LLM 없이 바로 카드를 만든다
- 실측 (11/20, 목업 4건): 한 요청 2.6~3.6초, LLM 호출 2~3번. 동명 후보는 소재지와 설립연도를 근거로 사용자에게 묻고, 없는 회사는 띄어쓰기를 바꿔 한 번 더 찾은 뒤 답했다

### 하는 일 세 줄 요약 (CDC-26, 11/22)

기업 카드에 "하는 일 세 줄 요약"을 붙인다 (PRD 04, 시간이 남을 때 하는 P2 기능). 사업보고서 "사업의 개요" 문단을 수치 없이 문장으로만 3줄 요약하고 공시 원문 링크를 붙인다. 숫자 계산은 코드, 긴 공시 문서의 해석은 AI라는 역할 분담을 보여주는 장면이다.

| 파일 | 하는 일 |
|---|---|
| `lib/business-summary.ts` | 문장 나누기, 숫자 문장 제외, 3줄 고르기(규칙 요약), 카드에 보일 상태 정하기, 같은 기업 캐시. 외부 API와 LLM을 부르지 않는다 |
| `lib/real/business-overview.ts` | OpenDART 공시검색으로 최신 사업보고서를 찾고, 문서 API(원문 ZIP)를 받아 "사업의 개요" 문단을 뽑는다. 앱은 부르지 않고 스크립트와 테스트만 쓴다 |
| `lib/agent/summarize.ts` | 작은 모델 요약기. 답이 규칙(정확히 3줄, 숫자와 주소 없음, 줄 길이)을 어기면 버리고 규칙 요약으로 대신한다. 스크립트에서만 쓴다 |
| `scripts/build-business-summaries.mts` | 시연 기업 4곳(카카오, 무신사, 컬리, 당근마켓)의 요약을 만들어 `data/real/business-summaries.json`에 쓴다 |
| `data/real/business-summaries.json` | 사전 계산 결과. 키는 OpenDART 고유번호. 시연 기업 4곳의 결과가 들어 있다 (11/22 실행) |

**카드에 보이는 세 상태** (`BusinessSummary`, 자세한 것은 `docs/schema.md` 3-1)

| 상태 | 언제 | 화면 | 판단 로그 |
|---|---|---|---|
| 요약 있음 | 개요를 요약함 | 3줄 + 원문 링크 (목업은 "가상 링크") | `tool_call` get_business_summary |
| 공시 없음 | 사업보고서가 없는 기업 (확인한 결과) | "공시 없음", 요약은 보여주지 않음 | `info` |
| 확인 불가 | 아직 계산하지 않음, 또는 조회 실패 | "확인 불가"와 이유 | `unavailable` |

- 목업 모드: 기업 데이터의 `businessOverview`(가상 문단)를 규칙으로 요약한다. LLM을 부르지 않는다. 목업 30곳 중 상장 5곳만 문단이 있고 나머지 25곳은 "공시 없음"
- 실데이터 모드: `data/real/business-summaries.json`에 기업이 있으면 그 상태를 그대로 쓰고, 없으면 "확인 불가"다. 사업보고서가 없는 기업은 `{ "status": "no_report" }`로 저장해서 "아직 계산 안 한 기업"과 구분한다
- 원문 전체는 저장하지 않는다. 저장하는 것은 요약 3줄, 원문 링크(`dartViewerUrl`), 확인 날짜다
- 숫자는 코드만 만든다 (CLAUDE.md 3번): 규칙 요약은 숫자가 든 문장을 걸러 내고, 모델 요약은 검증에서 숫자가 나오면 버린다
- 카드 화면: 요약 블록은 기업 카드 안에서 지표 펼치기 아래, "기업 카드 저장하기" 버튼 위에 붙는다 (`components/company-card.tsx`의 `BusinessSummaryBlock`). 스타일은 새 디자인 규칙(흰 바탕, 1px 회색 선, 그림자 없음, 모서리 4px, 토큰만 사용)을 따르는 `app/globals.css`의 `.cc-biz`다
- 같은 기업은 두 번 부르지 않는다: 앱 안에서는 기업마다 한 번만 계산하고, 스크립트는 이미 저장된 기업을 건너뛴다 (실패는 저장하지 않아서 다시 돌리면 실패한 기업만 다시 시도한다)
- 다시 계산: `node scripts/build-business-summaries.mts` (`--dry`는 네트워크 없이 계획만 출력, `--force`는 저장된 기업도 다시 받기, `--llm`은 작은 모델로 요약). `.env.local`의 `OPENDART_API_KEY`(`--llm`이면 `ANTHROPIC_API_KEY`도)를 읽고 키는 출력하지 않는다
- **실행 결과 (11/22, `--llm`):** 시연 기업 4곳(카카오, 무신사, 컬리, 당근마켓)이 모두 `ok`이고 방식은 `llm`(AI 요약), 확인일은 2026-11-22로 `data/real/business-summaries.json`에 들어 있다. 실제 DART 사업보고서(2025.12) 원문으로 "사업의 개요" 추출을 사람이 확인했다. 사업보고서가 없는 기업("공시 없음")은 이번 4곳에 없어서 실제 파일로는 확인하지 못했고 테스트(가짜 응답)로만 확인했다
- 실행에서 고친 것: 카카오 문서의 제목이 `1. (제조서비스업)사업의 개요`처럼 업종 괄호가 붙어 있어서 처음에는 추출에 실패했다. 같은 문서에 `(금융업)사업의 개요`도 있어서 첫 번째를 쓴다. 규칙을 고치고 테스트(RBO-05b, 05c)를 추가했다. 확인 날짜가 UTC 기준이라 한국 새벽에 하루 전으로 찍히던 것도 한국 시간으로 고쳤다
- 모델 답은 호출마다 달라서, 검증(3줄, 숫자 없음)을 통과하지 못하면 규칙 요약(원문 문장 선택)으로 대신한다. 카카오가 한 번 그렇게 저장되어서 카카오만 다시 받았다. 한 기업만 다시 받으려면 결과 파일에서 그 기업 항목을 지우고 `--llm`으로 돌린다 (나머지는 건너뛴다)
- AI 요약은 원문 표현을 비슷한 말로 바꾸거나 한 부문의 일을 사업 전체의 일처럼 쓸 수 있다. 카카오 3번째 줄("아티스트 육성과 글로벌 시장 확장")은 원문의 "아티스트를 양성"(뮤직 부문)과 "글로벌 시장으로 서비스 영역을 확장"(게임 부문)을 합쳐 쓴 것이다. 근거는 원문에 있어서 그대로 두었다 (11/22 사람 확인)
- 마감(11/23 17:00) 뒤에는 데이터를 바꾸지 않는다. 결과 파일을 다시 만들면 AI 요약 문장이 달라지므로 마감 전에만 한다
- 카카오와 같은 이름의 폐업 법인(00918444)은 대상이 아니라서 실데이터 모드에서 "확인 불가"로 보인다

### 실데이터: 시연 기업 사전 계산 (CDC-15, 11/20)

실행 중에는 외부 API를 부르지 않는다. 시연 기업만 미리 계산해 `data/real/companies.json`에 두고, `USE_MOCK=false`면 앱이 이 파일만 읽는다. 목록에 없는 회사는 "아직 준비되지 않은 회사"로 안내하고, 입력창 아래에 출처와 볼 수 있는 회사를 적는다.

| 파일 | 하는 일 |
|---|---|
| `scripts/build-real-companies.mts` | 사전 계산. OpenDART, 국민연금 파일, 국세청을 한 번 불러 `data/real/companies.json`을 쓴다 |
| `lib/real/dart.ts` | OpenDART 응답 -> 재무 3지표, 근속 |
| `lib/real/nps.ts` | 국민연금 파일 행 -> 고용 흐름, 보상 추정, 업종 평균 |
| `lib/real/assemble.ts` | 조각을 기업 카드(`Company`) 하나로. 리스크(국세청 휴폐업, 감사의견) |
| `data/real/targets.json` | 시연 기업 목록과 유형 판정(사람이 정함) |
| `data/real/manual.json` | 사람이 공식 자료에서 확인한 값 (R&D 비율, 등록 특허, 투자). 원문 링크와 확인 날짜 필수 |

- 다시 계산: `node scripts/build-real-companies.mts` (`.env.local`의 키를 읽고, 국민연금 파일은 레포 옆 `../data-raw/nps`의 최신 월과 12개월 전 월 두 개)
- 화면 확인: `NEXT_DIST_DIR=.next-live USE_MOCK=false USE_AGENT=false npx next dev --port 3200`
- 언제 다시 계산하나: 코드를 커밋할 때마다 하는 게 아니다. 아래 셋 중 하나가 바뀔 때만 돌리고, 바뀐 `data/real/companies.json`을 같이 커밋한다
  1. `data/real/targets.json`(시연 기업 추가·삭제, 유형 판정) 또는 `data/real/manual.json`(사람이 확인한 값)을 고쳤을 때
  2. `lib/real/` 변환 코드나 스크립트를 고쳤을 때
  3. 원본 데이터가 새로 나왔을 때 (국민연금 파일 새 달 분, 새 사업보고서). 국민연금은 매달, 사업보고서는 매년 3월쯤 나오지만 제출 마감(11/23 17:00) 뒤에는 데이터를 바꾸지 않으므로, 마감 전에 마지막으로 한 번 돌리고 고정한다
- 하는 일 세 줄 요약(CDC-26)도 같은 방식이다: `scripts/build-business-summaries.mts`가 결과를 `data/real/business-summaries.json`에 두고 앱은 그 파일만 읽는다. 위 "하는 일 세 줄 요약" 참고
- 비상장인데 재무 숫자가 API(XBRL)에 없는 회사(예: 당근마켓은 사업보고서를 내지만 API에 재무가 없음, 감사보고서만 내는 회사)는 OpenDART 문서 원문의 별도 손익계산서 숫자를 `manual.json`에 옮기고 원문 링크를 붙인다
- 재무 기준은 별도 재무제표로 통일한다. 이유와 예외는 README "실데이터" 항목
- 재무는 별도 재무제표를 먼저 쓴다. 입사하는 법인 자체를 보고, 국민연금(사업장)과 직원 현황(법인)과 단위를 맞추기 위해서다
- 국민연금 매칭: 사업자등록번호 앞 6자리만 공개라 앞 6자리와 사업장명이 모두 같은 한 행만 쓴다. 앞 6자리만으로는 다른 회사가 수십 곳 걸린다
- 보상 추정: 고지금액 / 가입자 / 보험료율(2025년 9%, 2026년 9.5%) x 12. 업종 평균도 같은 방법(같은 국민연금 업종코드, 가입자 10명 이상 법인, 표본 30곳 이상)으로 계산해 비교한다. 평균이 기준소득월액 상한(2026-07부터 659만 원)의 90% 이상이면 실제보다 낮게 나오므로 "이상"으로 표시한다
- 대표자는 OpenDART에 공시된 이름을 쓴다 (화면 표시 전용, LLM에 보내지 않음). 후보 칩에는 상장, 폐업 같은 상태 꼬리표를 붙인다 (11/21)
- 실측 (11/20, 카카오): 상장 법인은 9개 중 7개 값(재무 3, 고용 흐름, 보상, 근속, 리스크). R&D 비율은 수동 확인 대기. 같은 이름의 비상장 법인(2006년 설립)은 국세청 기준 2014-10-01 폐업이라 리스크만 "해당(폐업)"으로 나온다

|---|---|---|---|

| `compute_indicators` | 10가지 지표 계산, 확인 불가 처리 | 코드 | LLM이 숫자를 만들지 않음. `lib/indicators.ts` |
| `search_job_postings` | 같은 기업·직무 3년차 공고, 없으면 유사 기업 | 코드 + LLM 판단 | **최대 리스크: 합법적 출처 확보** |
| `extract_competencies` | 공고에서 요구 역량 추출·정규화 | LLM (작은 모델) + 코드 | 표현 뽑기는 LLM, 사전 이름으로 맞추기와 미매칭 모으기는 코드(`lib/competencies.ts`) |
| `start_matchup` / `get_preference` | 맞대결 출제, 선호 가중치 계산 | 코드 | Bradley-Terry, 고정 대진 8강 토너먼트(7판). 화면에서 바로 계산하고(`lib/matchup.ts`) LLM 도구로 부르지 않는다. 유형 설명 한 문장만 `/api/preference`가 작은 모델로 쓰고(USE_AGENT=true일 때), 검사에 걸리면 규칙 문장 |
| `render_report` | 지표 + 선호 + 역량 갭 → 리포트 | LLM 문장 + 코드 레이아웃 | 면접 역질문 포함 |

## 세션 상태

브라우저 localStorage에 보관, 매 요청에 서버로 전송. 개인 식별 정보 없음. 최근 분석 기록과 그 판단 로그도 같이 저장해 다시 열어볼 수 있다. 전체 모양과 예시는 [`schema.md`](schema.md) 6장, 타입은 `lib/types.ts`의 `SessionState`.

## 비용 관리 (API 크레딧 약 20달러)

- 가벼운 단계는 작은 모델, 최종 리포트만 큰 모델
- 기업별 결과 캐시
- 시연용 기업 20~30곳 사전 계산, 새 기업 검색은 일일 횟수 제한
- 대화 전체 대신 세션 상태 + 최근 몇 턴만 전송
- 개발과 UI 작업은 `USE_MOCK=true`로
